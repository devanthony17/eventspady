# Eventspady

A premium event booking & management web app — discover events, book tickets, pay through
five channels, and check guests in with QR codes.

Built with **React 18 + Vite + Tailwind CSS**, plain JavaScript, path aliases, per-page SEO and
lucide icons. All imagery lives in `public/images` and is generated locally, so the app runs with
zero external asset requests.

---

## Quick start

```bash
npm install
npm run dev      # http://localhost:5173
```

Other scripts:

| Script | What it does |
| --- | --- |
| `npm run dev` | Vite dev server with HMR |
| `npm run build` | Production build to `dist/` |
| `npm run preview` | Serve the production build locally |
| `npm run images` | Regenerate every asset in `public/images` |

Sign in with **any email and password** — auth runs in demo mode. Pick "I am organizing" on the
sign-in screen to land in the organizer panel.

## What's in it

**For attendees**
- Home page with search, categories, featured/trending/online/free tabs, countdown spotlight and
  location-aware "near you" section
- Event catalogue with URL-driven filters (category, type, date, price, ticket type, city,
  distance), grid/list views, sorting and pagination
- Event detail with gallery, multi-day schedule, venue map, organizer profile, FAQ, share and
  **report event**
- Checkout with coupon validation, itemised taxes, and all six payment methods
- Order confirmation issuing a real **QR code per ticket**
- Dashboard: tickets, saved events, wallet + top-up, notifications, profile, settings

**For organizers**
- Panel overview with revenue chart and payout breakdown (gross → commission → net)
- Event list with live capacity, four-step create-event wizard
- Orders table with search and filters, coupon manager, guest list with comps
- **Scanner** that validates QR codes, catches duplicates and works offline

**Platform**
- Google Sign-in (OAuth 2.0) button, email/SMS verification states
- Multi-language and multi-currency switchers
- Blog, FAQ, pricing, about, contact, feedback, privacy, terms, 404 and maintenance mode
- Light/dark theme, persisted and system-aware

## SEO

Every page renders a `<Seo>` component (react-helmet-async) that emits title, description,
canonical URL, Open Graph and Twitter card tags, plus optional JSON-LD.

Structured-data helpers live in `src/components/ui/Seo.jsx`:

- `eventJsonLd(event)` → `schema.org/Event` with offers, location and aggregate rating
- `articleJsonLd(post)` → `schema.org/BlogPosting`
- `faqJsonLd(items)` → `schema.org/FAQPage`

Dashboard, checkout and auth routes pass `noIndex`.

```jsx
<Seo title="Nova Nights" description={event.tagline} image={event.cover} jsonLd={eventJsonLd(event)} />
```

## Images

`public/images` is generated by `scripts/generate-images.mjs` — deterministic SVG cover art,
category tiles, avatars, logos, the OG image and illustrations. Regenerate with `npm run images`;
the same seed always produces the same file, so re-running never churns the diff.

Reference them by absolute path: `/images/events/event-1.svg`.

To use real photography instead, drop files into `public/images/events/` and point the `cover` and
`gallery` fields in `src/data/events.js` at them.

## Theming

Brand colours, shadows and animations are defined in `tailwind.config.js` under `brand`, `accent`
and `ink` scales. Change `brand` to re-skin the whole app.

Dark mode is class-based. The theme is applied before first paint by an inline script in
`index.html`, so there is no flash, and `ThemeContext` keeps it in sync with the OS until the user
makes an explicit choice.

## Connecting a backend

The UI is backend-agnostic. Three seams are where real APIs plug in:

1. **`src/context/AuthContext.jsx`** — replace the `login`, `loginWithGoogle` and `register` bodies
   with real calls. Everything downstream only depends on the user shape they return.
2. **`src/data/*.js`** — swap the static exports for fetches (or feed them through React Query).
   Selectors like `getEventBySlug` and `eventsByOrganizer` are the only read surface.
3. **`src/pages/Checkout.jsx`** — `onSubmit` builds the order object and hands it to the
   confirmation page via `sessionStorage`; point it at your orders endpoint instead.

Coupon rules (`src/data/coupons.js`), taxes and commission (`src/lib/constants.js`) are already
isolated so they can come from an admin API without touching components.

## Accessibility

- Skip-to-content link, focus-visible rings on every interactive element
- Modals trap focus, lock scroll and close on Escape or backdrop click
- Semantic landmarks, labelled form fields, `aria-live` regions for toasts and quantity changes
- Full `prefers-reduced-motion` support (animations collapse to near-zero duration)
- Both themes meet contrast requirements for body text and UI chrome
